# 河牌会上线部署清单与操作手册

项目目录是 `D:\workspace\texas-holdem`。正式环境为单台 Linux 云服务器：Caddy 提供 HTTPS/WSS，Spring Boot 提供游戏服务，PostgreSQL 长期保存账号、活跃牌局和历史。

> 仅限熟人使用虚拟筹码娱乐。不要加入充值、提现、抽水、现金结算或可交易筹码；上线前确认服务器所在地、参与者所在地及云厂商的适用规则。

## 1. 准备

- 2 核、2～4 GB 内存、30 GB 磁盘的 Linux 云服务器，推荐 Ubuntu 24.04 LTS。
- 一个解析到服务器公网 IP 的域名，如 `poker.example.com`。
- Docker Engine 与 Docker Compose 插件。
- 安全组只公开 TCP 80、TCP/UDP 443；SSH 22 最好限制来源 IP。
- 中国大陆服务器需先确认 ICP 备案、公安联网备案和相关内容合规要求。

不要公开 PostgreSQL 5432 或应用 8080。当前 Compose 没有映射这两个端口。

## 2. 上线前验证

Windows：

```powershell
cd D:\workspace\texas-holdem
./scripts/verify.ps1
```

有 Docker 的 Linux 环境再验证 PostgreSQL：

```bash
sh scripts/verify-postgres.sh
```

后者使用临时容器分别测试空数据库和 V1 数据库升级到当前最新版本（V3），不接触正式数据。

## 3. 上传与配置

项目已经初始化本地 Git，默认分支是 `main`。推荐推送到私有仓库后在服务器克隆，便于审计和回滚。没有私有仓库时，可先生成不包含 `.git`、`.env`、本地数据库、备份和依赖目录的发布包：

```powershell
git archive --format=zip --output=texas-holdem-release.zip HEAD
scp .\texas-holdem-release.zip deploy@服务器IP:/tmp/
```

然后在服务器创建 `/opt/texas-holdem` 并解压。不要直接递归上传整个工作目录，否则容易把 `.env`、`data/`、`backups/` 或 `node_modules/` 一并带上。发布包方式没有 Git 历史，后续升级需重新上传发布包；长期使用仍建议私有仓库。

服务器上：

```bash
cd /opt/texas-holdem
cp .env.example .env
openssl rand -base64 36
nano .env
chmod 600 .env
```

`.env`：

```dotenv
DOMAIN=poker.example.com
POSTGRES_PASSWORD=替换为刚生成的长随机密码
```

域名不带协议、路径和末尾斜杠。不要提交 `.env`、备份或真实密码。

## 4. 第一次启动

```bash
docker compose config
docker compose up -d --build
docker compose ps
docker compose logs -f --tail=200 app web postgres
```

PostgreSQL 健康后才启动应用，应用健康后才启动 Web。DNS 和 80/443 正确时，Caddy 会自动申请 HTTPS 证书。

```bash
curl -fsS https://你的域名/actuator/health
```

结果应包含 `"status":"UP"`。

## 5. 创建首个管理员

程序不会生成默认账号或启动密码。先在可信电脑生成 BCrypt 12 哈希，密码不会进入命令历史：

```powershell
./scripts/hash-password.ps1
```

Linux/macOS（本机需 JDK 和 Maven）：

```bash
sh scripts/hash-password.sh
```

复制完整的 `$2a$...` 或 `$2b$...` 输出，然后在服务器进入 PostgreSQL：

```bash
docker compose exec postgres psql -U poker -d poker
```

在 `psql` 内执行，替换用户名、昵称和哈希：

```sql
insert into user_accounts
  (id, username, password_hash, display_name, created_at, role, enabled, updated_at, auth_version)
values
  (gen_random_uuid()::text, 'admin', '$2a$12$替换为完整哈希', '管理员',
   current_timestamp, 'ADMIN', true, current_timestamp, 0);
```

```sql
select username, display_name, role, enabled from user_accounts;
\q
```

用这个账号登录，在“管理”中创建玩家账号。管理员重置的临时密码不会强制首次修改，可以直接提醒玩家登录后自行修改。

## 6. 上线验收

用两个浏览器或普通窗口加无痕窗口验证：

1. 管理员创建玩家，验证禁用、重新启用和重置密码。
2. 玩家修改昵称；验证当前密码后修改密码。
3. 玩家 A 建房，玩家 B 只凭邀请码/密码加入，其他账号看不到邀请码。
4. 两人入座完成一手牌，确认底牌只对本人显示。
5. 行动中刷新、短暂断网再恢复，确认返回原桌且没有重复扣筹码。
6. 在翻牌前、翻牌和河牌阶段分别重启应用，重新登录后继续。
7. 等待一次超时，确认只自动过牌或弃牌一次。
8. 管理员关闭房间，确认成员收到提示且不能再操作。
9. 历史记录只对参与者可见。
10. 手机网络下检查下注控件、连接遮罩和复制邀请码。

重启应用：

```bash
docker compose restart app
docker compose logs --tail=100 app
```

登录会话本身不保证跨重启；重新登录后，牌局会从数据库恢复。

## 7. 备份与恢复

```bash
cd /opt/texas-holdem
sh scripts/backup-postgres.sh
ls -lh backups
```

脚本保留最近 14 天的本机备份。还要把备份加密复制到另一台机器或对象存储，并定期演练恢复。

恢复会覆盖当前数据库：

```bash
sh scripts/backup-postgres.sh
docker compose stop app
docker compose exec -T postgres psql -U poker -d postgres -c "DROP DATABASE poker WITH (FORCE);"
docker compose exec -T postgres psql -U poker -d postgres -c "CREATE DATABASE poker OWNER poker;"
gunzip -c backups/指定备份.sql.gz | docker compose exec -T postgres psql -U poker -d poker
docker compose start app
```

恢复后检查健康状态、登录、活跃房间和历史。

## 8. 升级与回滚

避开正在进行的牌局，记录当前版本并先备份：

```bash
PREVIOUS_REVISION=$(git rev-parse HEAD)
echo "$PREVIOUS_REVISION"
sh scripts/backup-postgres.sh
git pull --ff-only
docker compose up -d --build
docker compose ps
curl -fsS https://你的域名/actuator/health
```

Flyway 自动迁移数据库。不要让旧应用连接已升级数据库。若新版本异常，先停止应用并切回刚才记录的版本：

```bash
docker compose stop app
git checkout "$PREVIOUS_REVISION"
docker compose up -d --build
```

只有确认数据库迁移向后兼容时才可直接启动旧应用。本次升级若包含不兼容迁移，应保持应用停止，按第 7 节从升级前备份恢复数据库，再启动旧版本并完整验收。确认稳定后再把仓库切回维护分支；不要在生产目录长期停留于未记录的 detached HEAD。

禁止对含用户数据的部署随意执行 `docker compose down -v`，它会删除数据卷。

## 9. 日常运维

```bash
docker compose ps
docker compose logs -f --tail=200 app web
docker compose restart app
docker system df
```

每个容器日志限制为 3 个、每个 10 MB。仍需定期检查磁盘、重启次数、异常登录和应用错误。日志可包含房间、手牌、用户、`actionId` 和错误原因，不得记录密码、底牌、完整牌堆或洗牌种子。
