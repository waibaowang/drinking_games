# 河牌会上线部署清单与操作手册

本文对应项目根目录：`D:\workspace\texas-holdem`。

目标部署方式：一台 Linux 云服务器运行 Docker Compose，由 Caddy 自动提供 HTTPS，Spring Boot 运行游戏服务，PostgreSQL 保存账号和已完成牌局。

> 本项目仅适合朋友之间使用虚拟筹码娱乐。不要加入充值、提现、抽水、现金结算或可交易筹码。

## 一、上线前还需要准备什么

### 1. 云服务器

推荐起步配置：

- Ubuntu 24.04 LTS 64 位
- 2 核 CPU
- 2～4 GB 内存
- 30 GB 以上系统盘
- 独立公网 IPv4
- 能长期开放 TCP 80、TCP 443

几桌朋友局通常不需要更高配置。服务器地域尽量靠近主要玩家。

### 2. 域名

准备一个域名或子域名，例如：

```text
poker.example.com
```

在域名服务商处添加 DNS 记录：

| 类型 | 主机记录 | 记录值 |
|---|---|---|
| A | `poker` | 云服务器公网 IPv4 |

如果服务器配置了 IPv6，再添加 AAAA 记录；没有正确配置 IPv6 时不要添加 AAAA，以免部分玩家连接失败。

等待解析生效后，在本机检查：

```powershell
nslookup poker.example.com
```

返回的 IP 必须等于云服务器公网 IP。

### 3. 备案与合规

如果服务器位于中国大陆，应先通过云服务商办理 ICP 备案。工业和信息化部现行规则要求，在中国境内提供非经营性互联网信息服务应履行备案手续，并在主页按要求展示备案编号。网站正式联通后，还应根据适用要求办理公安联网备案。

- [工信部：非经营性互联网信息服务备案管理办法](https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2024/art_84a0cfa0ebd049bbbe751dca9a008e56.html)
- [全国互联网安全管理服务平台](https://beian.mps.gov.cn/)
- [中央网信办：计算机信息网络国际联网安全保护管理办法](https://www.cac.gov.cn/2014-10/08/c_1112737294.htm)

如果使用中国大陆以外的服务器，通常不走大陆 ICP 备案流程，但仍需遵守服务器所在地及参与者所在地的法律和云厂商规则。德州扑克题材可能受到云厂商内容审核；上线前应向所选云厂商确认“无真钱、无充值、私人虚拟筹码牌局”是否允许。

### 4. 上线前建议补强

目前代码已经可以部署，但如果域名会公开传播，建议先完成以下项目：

- 增加全站注册邀请码或关闭自由注册，避免陌生人大量注册。
- 对登录、注册、加入房间和聊天接口增加限流。
- 增加管理员封禁账号、关闭房间和清理聊天的后台能力。
- 增加未完成牌局快照；当前服务器重启后，活跃房间需要重新创建。
- 确认隐私说明和数据保留策略；数据库中会保存账号及已完成牌局摘要。
- 至少进行一次 4～6 人、手机与电脑混合的实际牌局测试。

如果只是把不公开的地址发给少数熟人，可以先上线当前版本，但仍应使用强密码、HTTPS 和定期备份。

## 二、配置云服务器安全组

在云厂商控制台设置入站规则：

| 协议 | 端口 | 来源 | 用途 |
|---|---:|---|---|
| TCP | 22 | 最好限制为你的固定 IP | SSH 管理 |
| TCP | 80 | `0.0.0.0/0` | HTTPS 证书验证及跳转 |
| TCP | 443 | `0.0.0.0/0` | 网站和 WebSocket |
| UDP | 443 | `0.0.0.0/0` | HTTP/3，可选但建议 |

不要开放以下端口：

- 5432：PostgreSQL
- 8080：Spring Boot

项目的 Compose 文件没有将这两个端口映射到公网。

## 三、第一次连接服务器

在本机 PowerShell 中执行：

```powershell
ssh root@服务器公网IP
```

推荐随后创建普通管理用户，并使用 SSH 密钥登录：

```bash
adduser deploy
usermod -aG sudo deploy
mkdir -p /home/deploy/.ssh
cp /root/.ssh/authorized_keys /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys
```

确认普通用户能登录后，再考虑关闭 SSH 密码登录和 root 远程登录。不要在尚未验证密钥登录前关闭当前登录方式。

## 四、安装 Docker Engine 与 Compose

以下命令适用于 Ubuntu 24.04/22.04，使用 Docker 官方 APT 仓库。Docker 官方提醒：容器公开端口可能绕过部分 UFW 规则，因此仍应以云厂商安全组为第一道边界。

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker run --rm hello-world
```

官方安装说明：[Install Docker Engine on Ubuntu](https://docs.docker.com/engine/install/ubuntu/)

让当前用户可以运行 Docker：

```bash
sudo usermod -aG docker "$USER"
exit
```

重新 SSH 登录后验证：

```bash
docker version
docker compose version
```

注意：`docker` 用户组基本等同于 root 权限，只加入可信的服务器管理员。

## 五、把项目上传到服务器

### 方式 A：使用 Git 仓库，推荐

先把本地项目提交到你的私有 Git 仓库，然后在服务器执行：

```bash
sudo mkdir -p /opt/texas-holdem
sudo chown "$USER":"$USER" /opt/texas-holdem
git clone 你的私有仓库地址 /opt/texas-holdem
cd /opt/texas-holdem
```

不要把 `.env` 提交进 Git。

### 方式 B：直接从 Windows 上传

本机 PowerShell：

```powershell
scp -r D:\workspace\texas-holdem deploy@服务器公网IP:/opt/
```

服务器上确认：

```bash
cd /opt/texas-holdem
ls
```

应能看到 `compose.yml`、`poker-server`、`poker-web` 等目录。

## 六、填写生产环境配置

在服务器项目目录执行：

```bash
cd /opt/texas-holdem
cp .env.example .env
openssl rand -base64 36
```

复制最后一条命令生成的随机字符串，然后编辑：

```bash
nano .env
```

示例：

```dotenv
DOMAIN=poker.example.com
POSTGRES_PASSWORD=这里替换为刚生成的长随机密码
```

要求：

- `DOMAIN` 只填域名，不带 `https://`，不带路径，不带结尾斜杠。
- 数据库密码不要含换行，不要发给其他人，不要提交到 Git。
- 确认 `.env` 权限：

```bash
chmod 600 .env
```

## 七、第一次上线

确认域名已经解析到服务器、80/443 已开放，然后执行：

```bash
cd /opt/texas-holdem
docker compose config
docker compose up -d --build
docker compose ps
```

第一次构建需要下载 Java、Node、PostgreSQL 和 Caddy 镜像，可能持续数分钟。

查看启动日志：

```bash
docker compose logs -f --tail=200 app web postgres
```

看到应用启动完成后，按 `Ctrl+C` 退出日志，不会停止容器。

Caddy 会在以下条件满足时自动申请并续期 HTTPS 证书：域名 A/AAAA 记录正确、80/443 可从公网访问、容器可以绑定端口、证书数据目录可持久化。本项目已配置持久化 Caddy 数据卷。

- [Caddy Automatic HTTPS 官方说明](https://caddyserver.com/docs/automatic-https)

## 八、上线验收

依次检查：

### 1. 服务健康

```bash
curl -fsS https://你的域名/actuator/health
```

正常结果应包含：

```json
{"status":"UP"}
```

### 2. 浏览器检查

- 访问 `https://你的域名`，确认没有证书警告。
- 注册两个测试账号。
- 一个账号创建带密码的房间。
- 另一个账号通过六位邀请码加入。
- 两边入座并开始一手牌。
- 检查底牌只对本人显示。
- 刷新页面，确认能重新进入当前房间状态。
- 测试手机 4G/5G 网络，排除仅局域网可用的问题。
- 等待一次行动超时，确认自动过牌或弃牌。
- 完成一手牌，检查边池、平分底池和聊天显示。

### 3. 服务器检查

```bash
docker compose ps
docker compose logs --tail=100 app
docker system df
```

三个服务都应为运行状态，日志中不应持续出现数据库或 WebSocket 错误。

## 九、日常运维命令

```bash
# 查看状态
docker compose ps

# 查看实时日志
docker compose logs -f --tail=200 app web

# 仅重启 Java 服务
docker compose restart app

# 重启全部服务
docker compose restart

# 停止服务但保留数据库
docker compose down

# 再次启动
docker compose up -d
```

不要随意执行：

```bash
docker compose down -v
```

`-v` 会删除项目声明的数据卷，可能导致数据库和 HTTPS 证书数据丢失。

## 十、数据库备份

手工备份：

```bash
cd /opt/texas-holdem
sh scripts/backup-postgres.sh
ls -lh backups
```

脚本会保留最近 14 天的本机备份。仅保存在同一台服务器上还不够，建议每天同步到对象存储或另一台机器。

设置每日 03:20 自动备份：

```bash
crontab -e
```

加入：

```cron
20 3 * * * cd /opt/texas-holdem && /bin/sh scripts/backup-postgres.sh >> /var/log/poker-backup.log 2>&1
```

定期检查备份文件确实在增长，并至少演练一次恢复。

## 十一、从备份恢复

恢复会覆盖当前数据库。先确认备份文件名，并额外保存一份当前备份：

```bash
cd /opt/texas-holdem
sh scripts/backup-postgres.sh
docker compose stop app
```

创建空数据库并导入指定备份：

```bash
docker compose exec -T postgres psql -U poker -d postgres -c "DROP DATABASE poker WITH (FORCE);"
docker compose exec -T postgres psql -U poker -d postgres -c "CREATE DATABASE poker OWNER poker;"
gunzip -c backups/你要恢复的文件.sql.gz | docker compose exec -T postgres psql -U poker -d poker
docker compose start app
docker compose logs --tail=100 app
```

恢复后重新执行健康检查和登录测试。

## 十二、版本升级

升级前先备份：

```bash
cd /opt/texas-holdem
sh scripts/backup-postgres.sh
```

如果使用 Git：

```bash
git pull --ff-only
docker compose up -d --build
docker compose ps
curl -fsS https://你的域名/actuator/health
```

如果升级后有问题，查看日志：

```bash
docker compose logs --tail=300 app web
```

数据库迁移由 Flyway 在应用启动时自动执行。涉及数据库结构的版本不要直接用旧程序连接已经升级过的数据库；回退前应阅读该版本说明，必要时从升级前备份恢复。

## 十三、基本安全维护

- 云服务器、Docker 和系统包每月检查更新。
- SSH 只使用密钥，限制 22 端口来源 IP。
- 不把 `.env`、数据库备份或用户数据放进公开仓库。
- 不开放 PostgreSQL 和 Java 服务端口。
- 每周检查磁盘、容器重启次数和异常登录。
- 对外只分享 HTTPS 地址，不分享服务器 IP、SSH 密钥或数据库密码。
- 房间密码不要与服务器、账号或邮箱密码相同。
- 出现账号撞库、垃圾注册或聊天滥用时，先停止公开注册或关闭站点，再补限流及管理功能。

系统更新示例：

```bash
sudo apt update
sudo apt upgrade
docker compose pull postgres web
docker compose up -d --build
```

更新前务必备份；不要在牌局进行时升级或重启服务器。

## 十四、常见故障

### 浏览器提示证书错误

检查：

```bash
nslookup 你的域名
docker compose logs --tail=200 web
sudo ss -lntup | grep -E ':80|:443'
```

常见原因是 DNS 尚未生效、80/443 未放行、域名填错、AAAA 指向错误 IPv6 或其他程序占用了端口。

### 页面能打开但操作不实时

检查 Java 和 Caddy 日志：

```bash
docker compose logs --tail=200 app web
```

确认使用的是 `https://` 地址，浏览器中的 WebSocket 应连接到 `wss://你的域名/ws`。

### 应用显示数据库连接失败

```bash
docker compose ps
docker compose logs --tail=200 postgres app
```

确认 `.env` 中 `POSTGRES_PASSWORD` 已填写，且没有在首次创建数据库后随意修改。如果必须修改数据库密码，需要同时在 PostgreSQL 中修改用户密码。

### 服务器磁盘快满

```bash
df -h
docker system df
docker image prune
```

不要执行会删除数据卷的清理命令。先检查日志、旧镜像和备份文件占用。
